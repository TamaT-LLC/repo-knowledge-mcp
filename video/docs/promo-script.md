# 紹介動画（ナレーション版）台本・絵コンテ

repo-knowledge-mcp の新しい紹介動画の台本、絵コンテ、アートディレクションをまとめた文書です。
実装とTTSが読む機械可読データは [src/promo/script.json](../src/promo/script.json) にあり、この文書と同じ内容を持ちます。
両者が食い違った場合は、ナレーション・テロップ・尺は `script.json` を正とします。

| 項目 | 内容 |
| --- | --- |
| 仮タイトル | 一行のレビューが、ルールになるまで |
| 出力 | 16:9（1920×1080）と 9:16（1080×1920）の2本。台本・ナレーション・尺は共通で、レイアウトだけを切り替える |
| フレームレート | 30 fps |
| 想定尺 | 52.8秒（1584フレーム）。8シーン |
| 音声 | 日本語AIナレーション（ByteDance Seed Audio、Higgsfield経由）＋BGM |
| 事実の出典 | v0.4.2 時点の [README](../../README.md)。README にない機能・数値・主張は入れない |

画面に出す PR、レビューコメント、ルール、`get_rules` の応答は README のサンプルをもとにした説明用の例で、実画面の録画ではありません。
該当シーンには画面右下に注記を入れます。

## 1. コンセプト

一行のレビューコメントを主人公にして、PR から次の実装の前に届くまでを、一本の線でたどる。

### 物語の切り口

既存の42秒版は「課題 → 仕組み（4ステップ）→ 機能 → CTA」という説明型の構成です。
新作は、README の例にある一つのレビューコメントを最初から最後まで追いかける、ロードムービー型の構成にします。

- 主人公は概念ではなく、実際の一文です。コメントは raw evidence、proposed、active と状態を変え、最後は `get_rules` の応答と3つのエージェントの画面に現れます。
- 蒸留は、コメントの文字列がルール文へ変形する「文字の diff モーフ」で見せます。共通部分が残り、不要な部分が消え、新しい語が入ることで「要点を抜き出す」ことを説明なしで伝えます。
- 画面全体は一本の線（以下 thread）の上に並んだステーションで、カメラは線に沿って進みます。最後にカメラを引いて全行程を見せ、ルールから元のレビューへ光が逆流することで「根拠をたどれる」ことを視覚的に示します。

### 物語の構造

| 段 | シーン | 役割 |
| --- | --- | --- |
| 起 | s01 | 主人公（一行のレビュー）の登場と願い |
| 承 | s02–s03 | 仕組みの名前と、手元に根拠を残す最初の一歩 |
| 転 | s04–s05 | 送るかどうかと承認を人間が決める。安全側の既定値を見せる山場 |
| 結 | s06–s08 | 次の実装の前にルールが届き、3つのエージェントで使われ、元のレビューへたどれる。CTA |

## 2. アートディレクション

### 配色トークン

夜の製図台をイメージした、インクネイビーの単色地に2色の信号色を置きます。
朱（accent）は「人間の判断」だけに使い、スカイ（accent2）は線・データ・エージェントに使います。
色の意味を固定することで、「人間が決め、AI が使う」という関係を色だけでも読めるようにします。

| トークン | HEX | 名前 | 用途 | bg とのコントラスト比 |
| --- | --- | --- | --- | --- |
| `bg` | `#0B1020` | Ink Night | 全シーン共通の背景 | — |
| `fg` | `#EEF2F8` | Cool Paper | 見出し、本文、コードの値 | 16.9 : 1 |
| `muted` | `#8B95AD` | Slate | ラベル、注記、OFF 状態、記号類 | 6.3 : 1 |
| `accent` | `#FF5A4E` | Signal Vermilion | 人間の判断の瞬間だけ（opt-in のトグル ON、approve、判子のリング） | 6.2 : 1 |
| `accent2` | `#6CC8FF` | Thread Sky | thread、主役トークン、コードのキー、`get_rules`、URL、active タグ | 10.2 : 1 |

補助色はトークンを増やさず、`fg` の不透明度で作ります。

| 用途 | 指定 |
| --- | --- |
| 区切り線・枠線（hairline） | `fg` 12% |
| パネル面（TTY フレーム内など） | `fg` 5% |
| 背景のドットグリッド | `fg` 4%、48px 間隔。カメラと一緒に動き、パンの移動感を出す |
| thread の発光 | `accent2` 25%、ぼかし 24px。主役トークンと光のパルスだけに使う |

塗りの上に文字を置くときは、`accent` と `accent2` のどちらの塗りでも文字色は `bg` にします。
`fg` を `accent` の塗りに乗せるとコントラスト比が 2.7 : 1 まで下がるため使いません。

### タイポグラフィ

| 役割 | 書体 | 16:9 | 9:16 |
| --- | --- | --- | --- |
| 見出し（headline） | Noto Sans JP 700、字間 0.02em、行送り 1.3 | 88px | 76px |
| ワードマーク | Space Grotesk 700 | 120px（s02）/ 64px（s08） | 80px（s02）/ 64px（s08） |
| 主役テキスト（コメント・ルール文） | Noto Sans JP 500、行送り 1.5 | 52px（s01）/ 44px（s04） | 48px / 44px |
| コード・パス・コマンド | Space Grotesk 500（下記「等幅の扱い」） | 36–44px | 34–40px |
| ステーション名・ラベル | Space Grotesk 500、大文字、字間 0.12em | 20–22px | 22px |
| 字幕（captions） | Noto Sans JP 500、`fg` 92% | 40px | 44px |
| 注記 | Noto Sans JP 400、`muted` | 18px | 20px |

欧文と和文が混ざる文字列は、既存動画と同じく `"Space Grotesk", "Noto Sans JP", sans-serif` の順で指定し、欧文字形を Space Grotesk から取ります。
両書体とも `video/public/fonts/` に同梱済みで、ライセンスも同梱されています。

#### 等幅の扱い

システム等幅（Courier New など）は使いません。
既存版は Courier New を使っており、環境によって字形が変わるうえ、新作の書体の統一感を崩すためです。

- コード、パス、コマンド、JSON のキーは Space Grotesk 500 で組み、`font-variant-numeric: tabular-nums` と字間 0.01em を指定します。
- 「コードらしさ」は字幅ではなく、色と記号で表します。キーとコマンドは `accent2`、値は `fg`、記号類は `muted`、行頭に `$` または `›` を置きます。
- 文字の桁揃えに依存するレイアウトは作りません。JSON は空白で揃えず、キー列と値列の2列グリッドで組みます。ターミナルの各行も別要素にします。
- `get_rules` の下線（アンダースコア）が行送りで欠けないよう、コード行の行送りは 1.3 以上にします。
- 将来どうしても等幅が必要になった場合は、OFL の等幅書体をライセンスごと `public/fonts/` に同梱します。今回の範囲には含めません。

### レイアウトシステム（16:9 と 9:16）

二つの出力は同じタイムライン、同じ音声、同じシーン尺を使い、thread の向きだけを切り替えます。
16:9 では thread が横に流れ、9:16 では左端を縦に流れます。
各要素は「現在のステーションのノード」を原点に配置するため、向きを変えても構成は崩れません。

| 項目 | 16:9（1920×1080） | 9:16（1080×1920） |
| --- | --- | --- |
| thread | y=780 の水平線。左 → 右へ進む | x=96 の垂直線。上 → 下へ進む |
| 現在のノードの位置 | x=120 に固定 | y=300 に固定 |
| ステーション間隔 | 1680px（次のノードが右端にのぞく） | 1500px |
| 余白（セーフエリア） | 左右120px、上96px、下72px | 左右72px、上240px、下400px（SNS の UI を避ける） |
| 見出し | 左上 x=120、y≈170–270 | x=156–1008、y≈280–460。最大2行、「、」で改行 |
| 内容エリア | y≈320–720 | y≈500–1300、x=156–1008 |
| 字幕 | 中央、y≈912–1000、最大幅1480px、1行 | 中央、y≈1360–1500、最大幅936px、最大2行 |
| 注記 | 右下 y≈1040 | 左 x=156、y≈1510 |

thread は `accent2` の2px線を不透明度55%で描き、2px の点線を14px 間隔で1フレーム1px ずつ流して、止まっている場面でも線が生きているように見せます。
ステーションのノードは直径14px のリング（線幅2px）で、横にステーション名を置きます。
既存版にあった右上の章番号、下部のフッター、進捗バーは置きません。進み具合は thread 自体が示します。

#### 主役トークン

主役トークンは、レビューコメントの先頭語を載せた小さなピルです。
カメラの焦点位置に付いて thread 上を移動し、シーンごとに状態を変えます。

| シーン | 表示 | 枠と塗り |
| --- | --- | --- |
| s01–s02 | 『GitHub API の応答は…』 | `accent2` 1px 枠 |
| s03 | ＋タグ『raw evidence』 | タグは `muted` 枠 |
| s04 | ルール文に変形、タグ『proposed』 | `accent2` 枠 |
| s05 | タグ『active』 | `accent2` 塗り、文字 `bg` |
| s06–s07 | `get_rules` の応答の rule 行、3つのエージェントの行 | active のまま |

### モーションの原則

| 項目 | 指定 |
| --- | --- |
| 登場のイージング | `Easing.bezier(0.22, 1, 0.36, 1)`、14–18フレーム |
| 退場のイージング | `Easing.bezier(0.64, 0, 0.78, 0)`、8–10フレーム |
| カメラ移動 | `Easing.bezier(0.65, 0, 0.35, 1)`、18フレーム。シーン境界の前後9フレームずつにまたがる |
| overview へのモーフ（s07 → s08） | 24フレーム。実スケールで縮小せず、ステーション間隔を補間で縮める |
| テキストの登場 | フェード＋上昇ではなく、thread の進行方向へのマスクワイプ（16:9 は左 → 右、9:16 は上 → 下） |
| 複数要素の時間差 | 3フレーム |
| タイプ表現 | 1フレーム1文字 |
| 字幕 | チャンクごとに4フレームで切り替え。移動はさせない |
| 同時に動かす要素 | カメラと thread 以外は最大2つ |
| バネ・バウンス | 使わない。落ち着いたプロダクト紹介のトーンを保つ |

- シーン転換はカットもクロスフェードもせず、カメラが thread に沿って次のステーションへ進むことで行います。映像全体を一続きのワンショットに見せる意図です。
- 各シーンの主要な動きは、ナレーションの語に合わせます。絵コンテでは字幕チャンク（c1、c2、c3）の開始を基準にキューを書いているため、実音声の尺が変わっても同期を保てます。
- すべての動きは `useCurrentFrame` から計算し、同じフレームを再現できるようにします。
- 文字の diff モーフ（s04）は、共通部分の位置を保ったまま、削除部分を朱の取り消し線 → 収縮（10フレーム）、追加部分をタイプで入れます。
- 朱のリング（s05 の approve）は1回だけ、12フレームで広がって消えます。映像全体で朱が面として光るのはこの一拍と s04 のトグルだけです。

### 音（ナレーションと BGM）

- ナレーションは落ち着いた中低音の日本語で、誇張のない平らな読みにします。シーンごとに1ファイル、計8本を生成します。
- BGM は控えめにします。96 BPM 前後の柔らかいパッドと細いパルスを想定し、ナレーション中は 10–12 dB 下げます。既存版の 132 BPM のシンセとは質感を変えます。
- カメラがステーションに到着する瞬間に、小さなクリック音を置きます。最後は BGM の余韻で終えます。

### 尺の見積もり方法

各シーンの尺は「前の間 + 読み上げ時間 + 後の間」で見積もりました。
読み上げ時間は、ttsText の文字数（空白を除く）を毎秒6.5文字で割った値です。
前の間は6フレーム（s01 だけ12フレーム）、後の間は9フレームで、ナレーション同士の間は約0.5秒になります。
CTA は読み取り時間を確保するため、7.0秒に固定しました。

| id | ttsText の文字数 | 読み上げ（6.5字/秒） | シーン尺 |
| --- | --- | --- | --- |
| s01 | 35 | 5.4秒 | 6.1秒 |
| s02 | 40 | 6.2秒 | 6.7秒 |
| s03 | 35 | 5.4秒 | 5.9秒 |
| s04 | 37 | 5.7秒 | 6.2秒 |
| s05 | 39 | 6.0秒 | 6.5秒 |
| s06 | 44 | 6.8秒 | 7.3秒 |
| s07 | 43 | 6.6秒 | 7.1秒 |
| s08 | 35 | 5.4秒 | 7.0秒（固定） |
| 合計 | 308 | — | 52.8秒 |

毎秒7文字で読めば合計は約49秒、毎秒6文字なら約56秒になります。
実音声を生成したら、シーン尺は「6フレーム + 実音声のフレーム数 + 9フレーム」で計算し直してください。
合計が55秒を超える場合は、Seed Audio の速度を 1.05 程度に上げるか、次の短縮候補を使います。

- s06：「エージェントが変更前に、」を「変更前に、」にする（7字減）。主語は画面の『coding agent』で補う。
- s02：「レビューの知見を、」を「レビューを、」にする（3字減）。

## 7. 実装者への申し送り

- `script.json` の `estimatedSeconds` は見積もりです。実音声の長さでシーン尺を計算し直し、合計を45–55秒に収めてください。
- 字幕チャンクの切り替え時刻は、実音声の無音区間から取るのが確実です。取れない場合は ttsText の文字数に比例して割り振ります。
- 9:16 の SNS 向けセーフエリア（上240px、下400px）には、背景と thread 以外を置かないでください。
- ポスター画像の候補は、s05 で approve が朱に塗られる瞬間か、s04 の diff モーフの途中です。
- 既存の42秒版（`src/Intro.tsx` ほか）には手を入れず、新作は `src/promo/` 以下に分けて実装する想定です。
