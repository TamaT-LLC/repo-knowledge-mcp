# 紹介動画（ナレーション版）ナレーション制作記録

紹介動画のナレーションは AI で生成した音声です。
声優や実在の人物の声ではありません。
生成には Higgsfield を使い、生成物の利用は Higgsfield の利用規約に従います。

台本は [src/promo/script.json](../src/promo/script.json)、演出は [promo-script.md](promo-script.md) を参照してください。
この文書には、声の選定、実際に読ませたテキスト、検証、後処理、再生成の手順を記録します。

## 1. 採用した声とパラメータ

| 項目 | 値 |
| --- | --- |
| モデル | `seed_audio`（ByteDance Seed Audio 1.0、Higgsfield 経由） |
| 声 | Ken（preset、男性）`ceee41dc-0ee8-59a7-b3e8-2744116fcb5e` |
| パラメータ | `voice_type: "preset"`、`format: "wav"`、`sample_rate: 48000`、`speech_rate: 8`、ほかは既定値 |
| Higgsfield プロジェクト | repo-knowledge-mcp promo video |
| 使用クレジット | 12.6（42ジョブ × 0.3。内訳は5章） |

`speech_rate` は 0 が標準です。
試し生成の話速（毎秒5.3字）のままだと合計尺が約58秒になる見込みだったため、8 に上げて台本の想定尺 52.8秒に近づけました。
仕上がりの合計は 54.03秒（1621フレーム）です。

## 2. 声の候補比較

s02-product の ttsText を `speech_rate: 0` で5つの声に読ませて比べました。
候補は、プレビュー音声の基本周波数から、台本の「落ち着いた中低音」に合いそうなものを選びました。

| 声 | 性別 | 基本周波数の中央値 | 話速 | ASR 一致度 | 所見 |
| --- | --- | --- | --- | --- | --- |
| Ken | 男性 | 120 Hz | 5.3字/秒 | 0.71 | 「MCP」「ルール」「使える」「変えます」を認識。区切りの位置が台本どおり。末尾が自然に減衰する |
| Marcus | 男性 | 120 Hz | 5.9字/秒 | 0.72 | 「変えます」が「キャリアます」になるなど訛りが疑われる。末尾が途切れている |
| Hana | 女性 | 203 Hz | 5.9字/秒 | 0.57 | 「ルール」を認識できず。発話の後にノイズの破裂がある |
| Naomi | 女性 | 184 Hz | 4.8字/秒 | 0.53 | 音量が小さい（平均 -31.7 dB）。認識が崩れる箇所が多い |
| Nora | 女性 | 157 Hz | 4.9字/秒 | 0.34 | 認識がほぼ崩れる |

話速は、句読点と空白を除いた読み上げテキストの文字数を、発話区間の長さで割った値です。
ASR 一致度は、認識結果と参照文の文字単位の類似度（difflib の ratio）です。
この比較だけは、ディスク容量の都合で軽量な vosk（`vosk-model-small-ja-0.22`）で行いました。
採用後の全シーンの検証は、4章のとおり whisper で行っています。

### 採用の基準と経緯

採用するテイクは、次の3点をすべて満たすものに限りました。

- 最後の音が自然に減衰し、その後に無音が続く。Seed Audio は最後の音を途中で切ったテイクを返すことがあり（全37テイク中16テイク）、それらはすべて不採用にした。
- 固有名詞の途中に不自然な間がない。
- whisper の文字起こしで、固有名詞と本文が妥当に読まれている。

シーンごとの経緯は次のとおりです。

- **s02、s08**：`レポ ナレッジ エムシーピー` と空白を入れると、語の間に 0.16〜0.4秒の間が入り、whisper にも「レポ、ナレッジ、MCP」と区切って聞き取られた。空白を削除した表記で、名前が一続きに読まれるテイクを採用した。`レポナレッジ エムシーピー`（空白1つ）も試したが、ナレッジとエムシーピーの間に最大1秒の間が入った。
- **s03**：以前の採用テイクは末尾の「す」が切れていたため、差し替えた。空白を削除した `ジーエイチシーエルアイ` と、末尾に「。」を重ねた表記も試したが、どちらも末尾が切れた。原文のままのテイクで末尾が自然なものを採用した。
- **s06**：以前の採用テイクは「ゲット」と「ルールズ」の間に約0.3秒の間があり、whisper に「Get、Rulers」と聞き取られた。空白を削除して再生成した。
- **s07**：以前の採用テイクは「クロード」と「コード」の間に約0.34秒の間があった。空白を削除しても、テイクによっては間が残った（6テイク中2テイク）。間がなく、末尾が自然なテイクを採用した。
- **s08**：製品名の読みが最もよいテイクを採用した。このテイクには、発話が終わって約1.2秒後に約0.15秒のノイズの破裂が入っているが、後処理で自動的に除いている（6章）。末尾が自然でノイズもないテイクもあったが、製品名が「Repona Reg MCPE」と聞き取られ、名前の途中に間があったため採用しなかった。
- **s01、s04、s05**：末尾を再確認し、自然に減衰していたので差し替えていない。
- 末尾に「。」を重ねる表記は、末尾切れを防ぐ効果が確認できなかったため採用していない。

## 4. whisper による検証

mlx-whisper の `mlx-community/whisper-large-v3-turbo` で、最終採用の8本（書き出した m4a）を文字起こししました。
条件は `language="ja"`、`temperature=0`、プロンプトなしです。
念のため `whisper-small-mlx` でも確認しました。

| id | whisper-large-v3-turbo の結果 | 判定 |
| --- | --- | --- |
| s01-hook | PRに残った一行のレビュー、その指摘を次の実装の前に。 | ピーアールを「PR」と認識。全文一致 |
| s02-product | RepoNarage MCPは、レビューの知見をAIが使えるルールに変えます。 | レポナレッジは一続きに読まれている。「ナレッジ」は「Narage」と聞き取られた（下記） |
| s03-local | ReviewはG.H.C.L.I.で取得し、根拠として手元に保存します。 | ジーエイチ シーエルアイを「GHCLI」と認識（small は「GH-CLI」） |
| s04-optin | ルール候補作りは明示的に許可した方法だけ、外部送信は規定で無効です。 | 全文一致（「既定」は同音の「規定」と表記） |
| s05-approval | ルールになるのは、規定では、人間がターミナルで根拠を確かめて承認した候補だけ。 | 全文一致（同上） |
| s06-rules | エージェントが変更前に Get Rules を呼ぶと、ファイルとタスクに合うルールが返ります。 | ゲットルールズを「Get Rules」と認識。全文一致 |
| s07-agents | Codexes、クロードコード、カーソルで同じ知見を元のレビューまでたどれます。 | クロードコード、カーソルを正しく認識。コーデックスは「Codexes」（small は「コーデックス」） |
| s08-cta | RipoKnowledge.mcpまずは対象のリポジトリでセットアップから | 製品名を「Knowledge」「mcp」と認識。全文一致 |

whisper は、カタカナで読んだ英語の固有名詞を英字の綴りで書くことが多く、綴りはテイクごとに揺れます（カーソルが Carcel、Carser、Carsol になるなど）。
そのため判定では、綴りの一致ではなく、音として妥当か、語が一続きに読まれているかを見ました。

- s02 の「ナレッジ」は、テイクを替えても whisper には「Narage」「Naledage」などと聞き取られました。同じ表記の s08 では「Knowledge」と認識されているので、読みの誤りではなく「ナレージ」寄りに聞こえる発音の癖と判断しました。追加の3テイクも改善しなかったため、ルールまで正しく聞き取れる現テイクを採用しています。
- s07 の「コーデックス」は、読点の前の「ス」がやや強く発音され、whisper には「Codexes」と聞き取られることがあります。small モデルは「コーデックス」と認識しています。

公開前に、s02 の「ナレッジ」と s07 の「コーデックス」を人の耳で一度確認してください。

## 6. 後処理と timeline.json

`scripts/build-promo-timeline.mjs` が、生の wav からナレーション音声と [src/promo/timeline.json](../src/promo/timeline.json) を作ります。
処理は決定的で、同じ入力からは同じ m4a と JSON ができます。

1. silencedetect（-50 dB、50ms）で発話区間を求め、前 30ms・後 80ms の余白を残してトリムします。先頭に 10ms、末尾に 50ms のフェードをかけます。
2. 端のノイズを除きます。60ms 未満の孤立した音（クリック）と、発話から 0.3秒以上離れた 0.2秒未満の音（TTS の破裂ノイズ）は発話に含めません。s02（先頭 0.02秒）、s06（先頭 0.08秒）、s08（末尾 0.15秒の破裂）がこれに当たります。
3. 発話が生の wav の終端まで続いている場合は、最後の音が切れている可能性が高いため、`WARNING` をログに出します。このテイクは作り直してください。
4. loudnorm の2パスで -16 LUFS、True Peak -1.5 dBTP、LRA 11 に正規化し、48kHz・AAC 160kbps の m4a で `public/audio/promo/narration/<scene-id>.m4a` に書き出します。AAC のエンコードでピークが目標を超えた場合は、超えた分（＋0.1 dB）だけ音量を下げて書き出し直します。今回は s07 だけ -0.30 dB の補正が入りました。仕上がりは -15.7〜-16.3 LUFS、True Peak は全ファイルで -1.8 dBTP 以下です。
5. 書き出した m4a の尺を ffprobe で測り、30fps のフレーム数に切り上げます。
6. 字幕の切り替え位置は、書き出した m4a の silencedetect（-35 dB、120ms）で求めます。ttsText を字幕と同じ句読点で区切って読みの長さ（かな1、漢字2、小書きかな0）を数え、その比から予測した位置の近くにある無音区間を、先頭から貪欲に割り当てます。予測位置から `max(0.5秒, 発話長の15%)` 以内に無音がない区切りは、前後の確定した区切りの間を読みの長さの比で按分します。
7. `captionTiming` は、すべての区切りが無音区間で決まれば `silence`、一つでも按分を使えば `ratio` です。s05 は「確かめて」と「承認した」の間に間がないため、2つ目の区切りだけを按分しました。
8. シーン尺は「先頭の間（s01 は12フレーム、ほかは6フレーム）＋ナレーションのフレーム数＋末尾の間9フレーム」です。s08-cta は最低210フレームです。

字幕の `startFrame` は発話の始まり、`endFrame` は発話の終わりに合わせているため、チャンクの間に無音の分だけ字幕のない区間ができます。
narration と captions のフレームは、シーン開始からの相対値です。

## 7. 再生成の手順

1. Higgsfield の `seed_audio` で、1章のパラメータのまま、3章の「実際の読み上げテキスト」を生成します。台本を変えたシーンだけ生成し直せば十分です。
2. 結果の wav を、一つのディレクトリに `<scene-id>.wav`（例：`s01-hook.wav`）の名前で8本そろえます。生の wav はリポジトリに入れません。
3. `video/` で次を実行します。ffmpeg と ffprobe が必要です。

```sh
node scripts/build-promo-timeline.mjs --raw <dir>
```

声や話速を変えた場合は `--voice-id`、`--voice-name`、`--speech-rate` を付けると、timeline.json の `voice` に記録されます。
実行すると、シーンごとのトリム範囲、尺、ラウドネス、除いたノイズ、字幕の区切り方がログに出ます。
`WARNING` が出たシーンは生成し直し、`captionTiming` が `ratio` になったシーンは字幕の切り替わりを映像で確認してください。
