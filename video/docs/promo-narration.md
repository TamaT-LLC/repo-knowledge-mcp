# 紹介動画（ナレーション版）ナレーション制作記録

紹介動画のナレーションは AI で生成した音声です。
声優や実在の人物の声ではありません。
生成には Higgsfield を使い、生成物の利用は Higgsfield の利用規約に従います。

台本は [src/promo/script.json](../src/promo/script.json)、演出は [promo-script.md](promo-script.md) を参照してください。
この文書には、声の選定、実際に読ませたテキスト、検証、後処理、再生成の手順を記録します。

## 1. 採用した声とパラメータ

| 項目 | 値 |
| --- | --- |
| モデル | `text2speech_v2`（Higgsfield 経由、エンジンは ElevenLabs） |
| 声 | Quinn（preset、女性）`80914268-dfae-4f76-8306-36f2d55f58f8` |
| パラメータ | `variant: "elevenlabs"`、`voice_type: "preset"`、`voice_id` の3つだけ |
| 出力 | mp3（44.1kHz、モノラル、128kbps） |
| Higgsfield プロジェクト | repo-knowledge-mcp promo video |
| 使用クレジット | 6.3（42ジョブ × 0.15。内訳は5章） |

`text2speech_v2` では話速やピッチを指定できません。
そのため timeline.json の `voice.speechRate` は `null`（話速を指定していない）です。
仕上がりの合計は 54.70秒（1641フレーム）です。
以前の Ken 版（54.03秒、1621フレーム）より 20フレーム長くなりましたが、[promo-script.md](promo-script.md) の目安（合計55秒以内）に収まっているため、速度の変更（atempo など）はしていません。

## 2. 声の選定

最初は Seed Audio（`seed_audio`）の Ken（男性）で作りましたが、日本語が外国語話者のアクセントに聞こえるという指摘を受けて、声を選び直しました。
Higgsfield の preset 113件のプレビュー音声はすべて英語で、日本語ネイティブの preset はありません。
そこで、日本語の自然さはエンジンの日本語能力に頼ることにし、`text2speech_v2` の ElevenLabs と MiniMax で6つの候補を作りました。
各候補に s02 と s05 の台詞を読ませ、試聴して Quinn を選びました。

| 候補 | エンジン | 性別 | 所見 |
| --- | --- | --- | --- |
| Quinn | ElevenLabs | 女性 | 製品名まで whisper の書き起こしと一致した。採用 |
| Brooks | ElevenLabs | 男性 | 製品名まで一致した。語尾の減衰途中でファイルが終わる |
| Maya | MiniMax | 女性 | 製品名の発音がテイクごとに崩れる |
| Hana | MiniMax | 女性 | 「エーアイが」が別の語に聞き取られる。候補の中で最も遅い |
| Xavier | MiniMax | 男性 | 製品名が崩れる。抑揚が英語寄りに聞こえる疑いがある |
| Ken | MiniMax | 男性 | 以前と同じ preset。「既定」が「否定」に聞き取られる |

アクセントの自然さは whisper では測れないため、候補の比較では whisper の結果を足切りだけに使い、最後は耳で選びました。
ほかに seed_speech、seed_audio の別の声、cozy_voice、vibe_voice も試しましたが、日本語として成立しないか、preset では生成できませんでした。
候補づくりには 2.75 クレジットを使いました（5章の合計には含めていません）。

話速は、句読点と空白を除いた読み上げテキストの文字数を、発話区間（書き出した m4a で、ピークから −40 dB を超える最初と最後の 10ms 窓の間）の長さで割った値です。

### 採用の基準

採用するテイクは、次の4点をすべて満たすものに限りました。

- 先頭と末尾が切れていない。ElevenLabs の出力は、発話の直前や直後でファイルが終わることが多い。最初の 5ms が −45 dB 以下で、最後の 5ms が −40 dB 以下（語尾が減衰しきっている）のテイクだけを採用した。42テイク中23テイクがこれを満たさなかった（先頭だけ3、末尾だけ14、両方6）。先頭が切れたテイクは、最初の子音が欠けて whisper に「デポナレッジ」「デビュー」と聞き取られることがあった。
- 固有名詞の途中に不自然な間がない。
- whisper の文字起こしで、読み間違いや欠落がない。
- 字幕の区切りの位置に無音があり、`captionTiming` が `silence` になる。

シーンごとの経緯は次のとおりです。

- **s01**：3テイクとも基準を満たし、違いは小さかった。最も短い t1 を採用した。3テイクとも、語尾「に」の減衰は 10〜15ms と短い。
- **s02**：1回目の3テイクは、2つが末尾切れ、1つが先頭切れ（whisper では「デポナレッジ」）だった。同じ表記で4テイクを追加し、素の書き起こしでも「レポナレッジMCP」となった t6 を採用した。t4 と t5 も両端は切れていなかったが、whisper に「ベポナレッジ」「デビュー」と聞き取られた。
- **s03**：1回目の3テイクはすべて末尾切れだった。同じ表記で4テイクを追加し、t5 を採用した。t4 と t6 も基準を満たしたが、t4 は素の書き起こしで「Review」と英字になり、t6 は発話が約1秒長かった。
- **s04**：1回目の3テイクはすべて末尾切れだった。4テイクを追加したが、基準を満たしたのは t6 だけだった。
- **s05**：1回目の3テイクは、すべて「確かめて」と「承認した」の間に無音がなく、字幕の2つ目の区切りが按分（`ratio`）になった。Ken 版も同じだった。「確かめて、承認した」と読点を加えた表記で3テイクを追加し、区切りに 0.28秒の間が入り、末尾が自然に減衰する t6 を採用した。
- **s06、s07**：1回目の3テイクのうち、先頭と末尾がともに切れていないのは1テイクずつだった（s06 は t1、s07 は t3）。どちらも whisper の結果に問題がなかったため、それを採用した。
- **s08**：1回目は、t1 が両端とも切れていた。t2 は発話が終わって 0.42秒後に 0.21秒の音があり（whisper では「ドッ」）、後処理のノイズ除去（0.2秒未満）の対象外だった。t3 は両端とも問題ないが、whisper の素の書き起こしが「Depo Knowledge MCP」だった。製品名を確かめるために3テイクを追加したところ、t4 と t5 は「レポナレッジ」と「エムシーピー」の間に 0.21〜0.32秒の間が入り、t6 は末尾切れだった。そのため t3 を採用した。

## 4. whisper による検証

mlx-whisper の `mlx-community/whisper-large-v3-turbo` で、書き出した m4a の8本を文字起こししました。
条件は `language="ja"`、`temperature=0` です。
プロンプトなしの書き起こし（素）と、「外来語や英字の略語はカタカナで書き起こす」と指示したプロンプト付きの書き起こしの2通りで確かめました。
このプロンプトには、確かめたい固有名詞そのものは含めていません。

| id | 素の書き起こし | カタカナ指示付きとの違い | 判定 |
| --- | --- | --- | --- |
| s01-hook | PRに残った一行のレビュー、その指摘を次の実装の前に。 | なし | 全文一致 |
| s02-product | レポナレッジMCPは、レビューの知見をAIが使えるルールに変えます。 | なし | 全文一致 |
| s03-local | レビューはGHCLIで取得し、根拠として手元に保存します。 | なし | 全文一致 |
| s04-optin | ルール候補作りは明示的に許可した方法だけ。外部送信は規定で無効です。 | なし | 全文一致（「既定」は同音の「規定」と表記） |
| s05-approval | ルールになるのは、規定では人間がターミナルで根拠を確かめて承認した候補だけ。 | なし | 全文一致（同上） |
| s06-rules | エージェントが変更前にGet Rulesを呼ぶと、ファイルとタスクに合うルールが返ります。 | なし | 全文一致（ゲットルールズを「Get Rules」と表記） |
| s07-agents | コーデックス、クロードコード、カーソルで同じ知見を、元のレビューまでたどれます。 | なし | 全文一致 |
| s08-cta | Depo Knowledge MCP、まずは対象のリポジトリでセットアップから。 | 製品名が「レポナレッジMCP」 | 素の書き起こしでは製品名の頭が「Depo」（下記） |

Quinn の「レ」は、素の書き起こしで D、N、V、B で始まる英字に綴られることがあります。
先頭が切れていないテイク（s02 の t7、s08 の t4）でも素の書き起こしは「Nepo Knowledge」で、カタカナ指示付きでは「レポナレッジ」でした。
候補比較のときの Quinn の台詞も同じでした。
日本語の「ら行」の弾き音を whisper が英語の子音として綴ったものと判断し、s08 の t3 を採用しました。
公開前に、s08 の製品名が「レポナレッジ」と聞こえるかを耳で一度確認してください。

## 6. 後処理と timeline.json

`scripts/build-promo-timeline.mjs` が、生の wav からナレーション音声と [src/promo/timeline.json](../src/promo/timeline.json) を作ります。
処理は決定的で、同じ入力からは同じ m4a と JSON ができます。

ビルドの前に、生成された mp3 を 48kHz モノラルの wav に変換し、末尾に 0.2秒の無音を足しています（7章の手順2）。
ElevenLabs の出力は発話の直後でファイルが終わることが多く、42テイク中36テイクで、発話の終わり（-40 dB）からファイルの終わりまでが 65ms 以下でした。
無音を足さないと、ビルドはファイルの終わりを発話の終わりとみなし、末尾 50ms のフェードが語尾そのものにかかって語尾が短くなります。
また、語尾が減衰しきっていても、多くのテイクで次の手順3の `WARNING` が出ます（1回目の24テイクでは23テイク）。

1. silencedetect（-50 dB、50ms）で発話区間を求め、前 30ms・後 80ms の余白を残してトリムします。先頭に 10ms、末尾に 50ms のフェードをかけます。採用テイクは発話の前の無音が 30〜45ms で、silencedetect の最小長 50ms に届かないため、どのシーンも先頭をトリムしていません。
2. 端のノイズを除きます。60ms 未満の孤立した音（クリック）と、発話から 0.3秒以上離れた 0.2秒未満の音（TTS の破裂ノイズ）は発話に含めません。今回の採用テイクには該当がありません。
3. 発話が生の wav の終端まで続いている場合は、最後の音が切れている可能性が高いため、`WARNING` をログに出します。末尾に無音を足した wav では出ないため、語尾の確認は無音を足す前に行います（7章の手順2）。
4. loudnorm の2パスで -16 LUFS、True Peak -1.5 dBTP、LRA 11 に正規化し、48kHz・AAC 160kbps の m4a で `public/audio/promo/narration/<scene-id>.m4a` に書き出します。AAC のエンコードでピークが目標を超えた場合は、超えた分（＋0.1 dB）だけ音量を下げて書き出し直します。今回は補正が入ったシーンはありません。仕上がりは、loudnorm の測定で -15.98〜-16.02 LUFS、ebur128 の測定で -15.6〜-16.1 LUFS です。True Peak は全ファイルで -1.9 dBTP 以下です。
5. 書き出した m4a の尺を ffprobe で測り、30fps のフレーム数に切り上げます。
6. 字幕の切り替え位置は、書き出した m4a の silencedetect（-35 dB、120ms）で求めます。ttsText を字幕と同じ句読点で区切って読みの長さ（かな1、漢字2、小書きかな0）を数え、その比から予測した位置の近くにある無音区間を、先頭から貪欲に割り当てます。予測位置から `max(0.5秒, 発話長の15%)` 以内に無音がない区切りは、前後の確定した区切りの間を読みの長さの比で按分します。
7. `captionTiming` は、すべての区切りが無音区間で決まれば `silence`、一つでも按分を使えば `ratio` です。今回は、s05 を含む全シーンが `silence` です。
8. シーン尺は「先頭の間（s01 は12フレーム、ほかは6フレーム）＋ナレーションのフレーム数＋末尾の間9フレーム」です。s08-cta は最低210フレームです。

字幕の `startFrame` は発話の始まり、`endFrame` は発話の終わりに合わせているため、チャンクの間に無音の分だけ字幕のない区間ができます。
narration と captions のフレームは、シーン開始からの相対値です。

timeline.json の `voice` には、生成に使った声を記録します。
`variant` はモデルのエンジン（ここでは `elevenlabs`）、`speechRate` は TTS に渡した話速で、渡していなければ `null` です。

## 7. 再生成の手順

1. Higgsfield の `text2speech_v2` で、1章のパラメータのまま、3章の「実際の読み上げテキスト」を生成します。先頭や末尾が切れたテイクが半分以上出るため、1シーンにつき3テイク以上を作ります。台本を変えたシーンだけ生成し直せば十分です。
2. mp3 をダウンロードし、先頭と末尾の音量を確かめます。最初の 5ms が -45 dB 以下で、最後の 5ms が -40 dB 以下のテイクだけを使います。

   ```sh
   ffmpeg -i take.mp3 -af "atrim=end=0.005,volumedetect" -f null - 2>&1 | grep mean_volume
   ffmpeg -i take.mp3 -af "areverse,atrim=end=0.005,volumedetect" -f null - 2>&1 | grep mean_volume
   ```

   使うテイクは、末尾に 0.2秒の無音を足した wav に変換し、一つのディレクトリに `<scene-id>.wav`（例：`s01-hook.wav`）の名前で8本そろえます。生の音声はリポジトリに入れません。

   ```sh
   ffmpeg -i take.mp3 -af apad=pad_dur=0.2 -ac 1 -ar 48000 -c:a pcm_s16le s01-hook.wav
   ```

3. `video/` で次を実行します。ffmpeg と ffprobe が必要です。

   ```sh
   node scripts/build-promo-timeline.mjs --raw <dir>
   ```

4. timeline.json のシーン尺が変わるため、BGM と効果音も `npm run audio:promo` で作り直します。

timeline.json の `voice` は、既定で1章の Quinn になります。
声を変えた場合は `--model`、`--variant`、`--voice-id`、`--voice-name`、`--speech-rate` を付けます。
`--model` を既定と違うモデルにした場合、`--variant` を付けなければ `variant` は `null` になります。
実行すると、シーンごとのトリム範囲、尺、ラウドネス、除いたノイズ、字幕の区切り方がログに出ます。
`captionTiming` が `ratio` になったシーンは、字幕の切り替わりを映像で確認してください。

## 8. 変更履歴

- **Seed Audio の Ken（初版）**：`seed_audio`、preset Ken（`ceee41dc-0ee8-59a7-b3e8-2744116fcb5e`）、`speech_rate: 8` で生成した。合計 54.03秒（1621フレーム）、42ジョブで 12.6 クレジット。Seed Audio は最後の音を切ったテイクを返すことがあり（37テイク中16）、固有名詞の途中の間をなくすために s02、s03、s06、s07、s08 を作り直した。日本語が外国語話者のアクセントに聞こえるという指摘を受けて、2章のとおり Quinn に差し替えた。
